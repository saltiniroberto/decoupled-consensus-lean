# Plan: clickable paper citations in the Lean files

For a fresh session to execute (written 2026-08-18). Goal: in VS Code, a citation like
`` (`def:recovery-timing`, lines 146–150) `` inside a `.lean` docstring becomes a link
that opens the right `.tex` file at the cited line. **Delete this file in the closing
commit**; record the outcome in CONTEXT.md and the machine-local install steps in
CONTEXT_LOCAL.md.

## Constraints, before anything

1. **Do not modify any `.lean` file.** The citations as written are the interface; they
   are verified by `make cites`, and the whole point is to make the existing text
   clickable. If a citation form turns out to be unlinkable, extend the tooling, not the
   docstrings.
2. **One grammar, one owner.** `tools/check_citations.py` owns the citation grammar (its
   `LABEL`, `PROSE`, `INPAREN`, `HEADER`, `ELIDED` regexes) and the label→file resolution
   (bare labels live in `latex-specs/*.tex`; `hft:`-prefixed labels in
   `latex-specs/full/height_filter_and_timeouts.tex`). Import from it — the generator
   below is a second consumer of the same constants, never a re-implementation.
3. Committed files may not contain absolute paths (repo rule); anything machine-specific
   is computed at runtime or lives in gitignored files.

## Architecture: a generated label map plus a thin link provider

Two pieces, because the label→file/line resolution needs the `.tex` sources and Python
already parses them, while the clickable part needs a VS Code extension:

### 1. `tools/citation_links.py` — the label map generator

* Imports the regexes and paths from `tools/check_citations.py`.
* Scans the same sources the checker scans and emits `.citation-links.json` at the
  repository root: for every `\label{...}` in `latex-specs/*.tex` and the `hft:` paper,
  the repo-relative tex path and the label's line number (and, where the checker computes
  environment spans, the span too).
* `.citation-links.json` is **gitignored** (add the entry) and regenerated by a new
  `make citation-links` target; wire the target into the `make mapping`-adjacent section
  of the Makefile and list it in `make`'s help text.

### 2. `tools/vscode-citations/` — the link provider extension

A minimal local VS Code extension: `package.json` (name it for the project, activation on
the `lean4` language and `*.lean` files) and `extension.js` registering a
`vscode.languages.registerDocumentLinkProvider` for Lean documents that:

* loads `.citation-links.json` from the workspace root (re-read on change; degrade to no
  links, never an error toast, when absent — tell the user once via the status bar or log
  that `make citation-links` arms it);
* scans each visible document for the citation forms (port the regex shapes; keep a
  comment pointing at `check_citations.py` as the source of truth);
* for `` `label` `` occurrences, links to the label's tex file at its line; for
  `lines a–b` next to a label, links the range text to line `a` of that label's file.
  Note both en-dash `–` and hyphen occur in the sources — the checker's `DASH` class
  covers this; reuse it;
* opens files at a line: try `vscode.Uri.file(abs).with({ fragment: 'L<line>' })` as the
  `DocumentLink` target first — VS Code honors `#L<line>` fragments on file URIs in most
  versions — and **verify it lands on the line**; if it does not, fall back to a
  registered command (`decoupled.openCitation`) invoked via a `command:` URI that calls
  `window.showTextDocument` with a `Selection` at the line. Do not ship the fragment
  variant unverified.

### Install and record

No marketplace publishing. Two supported installs, documented in a short
`tools/vscode-citations/README.md`:

* symlink or copy the folder into `~/.vscode/extensions/` (a folder with a valid
  `package.json` is loaded on restart), or
* `vsce package` and install the `.vsix`, for those who prefer it.

The machine-local step actually performed on this machine goes in `CONTEXT_LOCAL.md`
(gitignored), not in CONTEXT.md.
